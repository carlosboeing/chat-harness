# Chat Harness v0.3.1

This patch release adds first-class lifecycle management for the Chat Harness CLI itself.

It does **not** change the v0.3 Workspace persistence contract. Software update, Workspace setup, Workspace migration, and uninstall remain separate authority boundaries.

## First-class CLI updates

Chat Harness can now manage updates through a single channel-aware command:

```bash
chat-harness update --check
chat-harness update
```

- detects standalone release binaries, global npm installations, local development builds, and unknown/custom installations;
- reports the current version, latest version, installation channel, and executable path;
- exits successfully without mutation when already current;
- keeps `update --check` read-only, including when PATH ambiguity is detected;
- refuses mutation when installation provenance or PATH ownership is ambiguous.

For standalone binaries, updates:

- select the exact GitHub Release asset for the running OS and architecture;
- download the matching SHA-256 sidecar;
- verify the checksum before replacement;
- verify the staged binary reports the expected release version;
- replace transactionally on macOS/Linux with rollback if post-replacement verification fails.

For global npm installations, Chat Harness delegates ownership back to npm with:

```bash
npm install -g chat-harness@latest
```

and verifies the resulting installed package version.

## Safe uninstall

The new uninstall command removes Chat Harness software without coupling package removal to user data:

```bash
chat-harness uninstall
chat-harness uninstall --yes
```

Interactive use asks for confirmation. Non-interactive and JSON use require `--yes`.

Uninstall removes only the detected Chat Harness CLI/package and adjacent Chat-Harness-owned installation metadata. It never deletes or modifies Workspace/project data such as:

```text
AGENTS.md
.chat-harness/
_inbox/
Workstreams
Workbench artifacts
domain/project files
Google Drive Workspace content
```

There is deliberately no `--purge-workspaces` option.

## Installation provenance

New standalone and local-development installs write a narrow install-adjacent `.chat-harness-install.json` sidecar containing only the installation channel.

Existing pre-metadata standalone installs remain recognized at the documented default location:

```text
~/.local/bin/chat-harness
~/.local/bin/chat-harness.exe
```

Stable compiled binaries in other custom locations without provenance metadata fail closed rather than guessing ownership.

Local development builds remain identifiable by their injected `<package-version>-<git-sha>[-dirty]` version and are never silently replaced by a published release.

## Windows lifecycle handling

Windows update and uninstall do not try to overwrite or delete the currently running executable.

Instead, Chat Harness stages and verifies the requested operation, copies itself to a narrowly scoped temporary helper, exits, and lets that helper perform replacement or removal after the parent process has stopped.

The helper validates its target, staging, backup, metadata, job, and helper paths and is not a generic deferred file-operation mechanism.

## Automation and qualification

Lifecycle commands support the same machine-readable `--json` envelope model as the rest of the CLI.

The release includes deterministic coverage for:

- release lookup and network failure;
- checksum mismatch;
- unsupported OS/architecture;
- unwritable installation paths;
- PATH ambiguity;
- unavailable/failing npm;
- candidate and post-replacement version verification;
- POSIX rollback;
- Windows parent-process locking and rollback;
- unknown/custom installation refusal;
- development-build safety;
- uninstall Workspace-data boundaries.

Windows lifecycle behavior is also exercised in CI with a Windows x64 standalone build.

## Workspace compatibility

v0.3.1 does not migrate or rewrite Workspace state.

The boundaries remain:

```text
update      = update Chat Harness software
migrate     = transform an existing Workspace contract/schema (future)
setup       = create/reconcile managed Workspace scaffold
uninstall   = remove installed Chat Harness software
```

Existing v0.3.0 Workspaces require no lifecycle-specific migration.

## Upgrade from v0.3.0

Because `chat-harness update` is introduced by this release, upgrade from v0.3.0 once using the installation channel you already have.

npm:

```bash
npm install -g chat-harness@latest
chat-harness --version
```

Standalone macOS/Linux:

```bash
curl -fsSL https://raw.githubusercontent.com/carlosboeing/chat-harness/main/install.sh | sh
chat-harness --version
```

Standalone Windows:

```powershell
irm https://raw.githubusercontent.com/carlosboeing/chat-harness/main/install.ps1 | iex
chat-harness --version
```

After v0.3.1 is installed, future managed updates can use:

```bash
chat-harness update --check
chat-harness update
```
