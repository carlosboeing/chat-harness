# Chat Harness v0.3.7

This patch release adds a safe fallback path for canonical file replacement while preserving the existing, proven persistence instructions.

## Changed

### Safe fallback file replacement

Chat Harness continues to prefer normal in-place replacement because it preserves provider file identity and history where supported.

If an authorized in-place replacement fails after a normal retry, and the provider supports the required create/read/rename/delete primitives, the Project Instructions now allow a bounded copy-on-write fallback:

1. create and verify a complete temporary candidate;
2. re-read the canonical file to detect concurrent changes;
3. rename the canonical file to a unique backup;
4. promote the candidate;
5. re-read and verify the new canonical file;
6. delete the backup only after successful verification.

The last known-good copy is never deleted before the promoted replacement is verified. If promotion or final verification fails, the backup is restored when possible and the operation is reported as a persistence failure.

### Existing persistence behavior preserved

The existing Markdown/YAML/MIME/readback persistence instructions are unchanged. The fallback was appended after that block rather than rewriting or compressing it.

Regression coverage now locks the original persistence block unchanged and verifies that the fallback appears after it.

### Artifact-type scope

The fallback applies to canonical files/artifacts generally. Raw Markdown remains the primary Chat Harness durable format, but non-Markdown artifacts retain their own expected type/format verification.

### Project Instructions size guardrail

The Project Instructions engineering ceiling is now aligned with ChatGPT's 8,000-character limit. The canonical template remains below that ceiling.

## Compatibility

No Workstream schema, Workbench taxonomy, Source Policy version, or specialist Workspace contract changed in v0.3.7.

Existing v0.3.6 Workspaces should run:

```bash
chat-harness update
chat-harness setup
chat-harness validate
chat-harness doctor
```

For a recognized Chat-Harness-managed `AGENTS.md`, normal `setup` refreshes that file to the v0.3.7 generic instructions.

Normal `setup` does **not** replace an existing `.chat-harness/WORKSPACE.md` unless `--replace-workspace` is explicitly supplied.

For ChatGPT Projects, after refreshing the Workspace, copy the complete updated `AGENTS.md` into Project Instructions.
