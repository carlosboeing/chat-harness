# Chat Harness v0.4.0

This pre-1.0 release publishes the v1 implementation candidate merged since v0.3.7: manifest-backed setup, native non-clobbering reconciliation and Core version 2.

It is **not** host-accepted. Hosted ChatGPT acceptance runs still fail in the ways listed under [Known limitations](#known-limitations). Version `1.0.0` stays reserved for complete host acceptance and release signoff.

## Changed

### Core version 2

- The generic Project Instructions (`AGENTS.md`) move to Core version 2.
- The Workbench layout is `0-ideas`, `1-research`, `2-design`, `3-plans`, `4-reviews`. The v0.3 folder `2-decisions` is replaced by `2-design`.
- Ordinary multi-step Work now starts Workstream persistence before the agent answers. Read-only Work and simple answers still write nothing.
- Checkpoint completion includes a verified cleanup step for copy-on-write (COW) backups.
- Core stays under the 8,000-character ChatGPT Project Instructions limit.

### Manifest-backed setup

- A schema-1 `.chat-harness/manifest.yaml` records the Core and each selected Specialist bundle with exact digests. Workspace customization, Source Policy, optional folders and user data stay outside it.
- `--specialists <ids>` sets the exact desired set of the twelve embedded version-1 Specialists. `none` alone means Core only.
- Interactive setup offers a multiselect, additive folders and separate brownfield consent. It shows the semantic changes and asks for final approval.
- New options: `--scaffold-domain`, `--adopt-workspace`, `--replace-agents`.
- `--dry-run` inspects and plans only. It never writes.

See the [CLI reference](../cli.md) and [Specialists](../specialists.md).

### Native reconciliation and recovery

- Packaged native helpers apply non-clobbering moves on macOS and Linux (arm64, x64) and on Windows x64 local fixed NTFS volumes. There is no runtime compiler, source or network fallback.
- Setup holds an exclusive lease, stages updates, verifies backups, commits the manifest last and reads it back before it reports success.
- An interrupted transaction is recovered forward or rolled back at the tested boundaries. A state that cannot be proven fails closed and keeps its evidence.
- Windows network paths, reparse-point ancestors and unsupported filesystems fail closed.

See [Reconciliation and recovery](../reconciliation.md).

### Diagnostics

- `validate` and `doctor` report manifest health and pending transaction journals.
- They report recognized dated Workstream COW backups as errors.
- They never recover, clean up or change files.

### Software lifecycle

- Standalone install, update and uninstall carry the verified native helper.
- The PowerShell installer is tested on PowerShell 7 and 5.1.

## Breaking: existing v0.3.x Workspaces

- Setup no longer accepts `--specialist`, `--replace-workspace`, `--force` or version pinning.
- v0.4.0 refuses a Workspace created by v0.3.x. Such a Workspace has Chat Harness markers but no schema-1 manifest:
  - `validate` fails with `setup.legacy_workspace_unsupported`.
  - `setup` returns `user_action_required` and writes nothing.
- This release has no migration command and no step-by-step migration guide.

For an existing v0.3.x Workspace, choose one:

1. Keep using v0.3.7 for that Workspace.
2. Set up a new Workspace with v0.4.0, then move your own content into it by hand.

Qualification confirmed this behavior. A Workspace created by the published v0.3.7 package was refused by v0.4.0 setup, and no byte changed.

## Known limitations

Hosted ChatGPT runs:

- **Workstream initiation is not reliable.** The agent can answer ordinary Work without starting the Workstream. Both fresh, uncoached full-lifecycle runs of this change failed. Tracked in [#80](https://github.com/carlosboeing/chat-harness/issues/80).
- **Final checkpoint closeout can fail.** One run left a stale active COW backup beside the completed Workstream. Another run failed the final canonical Workstream update. Tracked in [#80](https://github.com/carlosboeing/chat-harness/issues/80) and [#82](https://github.com/carlosboeing/chat-harness/issues/82).
- **A stale Next action is not detected.** `validate` and `doctor` cannot detect a Next action that is structurally valid but out of date.
- **COW backups are only detected.** Recognized dated backups are reported. Nothing recovers them automatically. Tracked in [#82](https://github.com/carlosboeing/chat-harness/issues/82).
- **Connector writes can fail intermittently.** One file-reference test also showed an adapter type mismatch. Tracked in [#83](https://github.com/carlosboeing/chat-harness/issues/83).

Until these are resolved, reread the Workstream after the agent reports a checkpoint. If a write fails, reread the target, retry once if safe, keep the last good copy and treat persistence as incomplete.

Release scope:

- Manual first-party host acceptance and the 38-invariant release signoff are not complete.
- The ChatGPT Projects binding remains documented but not verified end to end. See [Compatibility](../compatibility.md).
- Tests prove recovery from process interruption at the tested boundaries. They do not prove OS-crash or power-loss durability.

## Upgrade

`chat-harness update` changes the software only. It never changes a Workspace.

For a new Workspace:

```bash
chat-harness setup <path>
chat-harness validate <path>
chat-harness doctor <path>
```

For ChatGPT Projects, copy the complete `AGENTS.md` into Project Instructions after setup. The CLI cannot check whether a hosted copy is current.
