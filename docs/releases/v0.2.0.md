# Chat Harness v0.2.0

**Harness engineering for AI assistants.**

This release introduces the current Workspace model: a smaller generic harness scaffold, stronger durable recovery semantics, and setup-time specialists for domain-specific work. It is an intentional clean contract break from the earlier pre-release Workspace shape.

## Workspace model

- makes `AGENTS.md` the canonical, self-contained generic Chat Harness instruction file;
- adds `.chat-harness/WORKSPACE.md` as the single Workspace-specific instruction extension;
- uses `.chat-harness/README.md` as a compact Workspace Map for routing and source ownership;
- scaffolds Workstreams, Procedures, Source Policy, Inbox, temp, and the Workbench taxonomy by default;
- keeps the user's domain corpus domain-defined instead of imposing universal Knowledge/Research/Projects-style folders;
- strengthens substantial-task recovery so relevant Workstreams are inspected before reconstructing state from chat history or model memory;
- clarifies that Workstreams hold compact current objective state while Workbench holds substantial durable working artifacts.

## Specialists

Setup now supports robust specialist seeds:

- `general`
- `research`
- `tech`
- `tax`
- `finance`
- `career`
- `shopping`
- `travel`

Use `chat-harness setup --specialist <id>` to seed Workspace-specific judgement and evidence standards. Specialists are setup-time seeds, not runtime agents or inheritance modes. Optional domain scaffolding remains explicit and additive.

## Setup and safety

- preserves unknown or user-owned brownfield content rather than silently adopting it;
- refreshes only recognizably Chat Harness-managed `AGENTS.md` files;
- preserves existing `WORKSPACE.md` by default;
- removes the old lifecycle architecture instead of carrying migration or compatibility machinery;
- retains the narrow Source Policy model and existing bounded capability/security principles.

## Documentation

The public documentation has been reorganized and expanded around the current architecture:

- restores the reader-facing explanation of what Chat Harness is and why it exists;
- adds a documentation landing page and dedicated specialist guide;
- expands Architecture, Concepts, Compatibility, and ChatGPT host-binding guidance;
- keeps current-facing docs focused on the current product rather than narrating pre-release version history.

## Upgrade note

Because this release intentionally changes the pre-release Workspace contract, existing early Workspaces are not automatically migrated. Review the current scaffold and setup behavior before applying it to an existing Workspace.
