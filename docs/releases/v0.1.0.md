# Chat Harness v0.1.0 — release notes draft

**Harness engineering for AI assistants.**

Chat Harness v0.1 is the first executable reference toolkit for applying harness-engineering discipline around long-running work with general-purpose AI assistants. It is not another agent runtime: the assistant continues to provide its model, conversation loop, files, connectors, tools, and native execution.

## Included

- minimal, reversible Workspace bootstrap with `AGENTS.md` and `.chat-harness/`;
- resumable Markdown Workstreams and optional lifecycle artifacts;
- optional Source Policy with deterministic v1 path/privacy semantics;
- `chat-harness setup`, `validate`, and `doctor` with stable human/JSON results;
- path-contained, brownfield-safe setup that does not silently rewrite existing user content;
- portable operating instructions covering progressive retrieval, source ownership, CREATE/CLOSE, currentness, authority, transparency, and recovery;
- a bounded GitHub-backed external capability mechanism with strict persistent-transport security gating;
- `linkedin.job.lookup` as the initial durable public-data capability;
- four synthetic reference Workspaces: travel planning, family administration, job opportunity evaluation, and scientific research;
- deterministic tests plus a 19-scenario behavioural eval catalog;
- standalone binaries for Linux x64/arm64, macOS x64/arm64, and Windows x64;
- SHA-256 sidecars and checksum-verifying installers;
- a secondary bundled Node/npm CLI path.

## Verified before publication

The release candidate has deterministic CI coverage for CLI/Workspace contracts, Source Policy, capability authority/security, Phase 0 dispatcher parity, examples/evals, public documentation, browser-runtime policy, package contents, and standalone/Node behaviour equivalence.

A five-platform private Actions smoke has built and executed the native standalone binaries with an empty `PATH`, proving the primary binaries do not require an installed Bun or Node runtime.

A real owner-authored private-main GitHub transport smoke also completed end to end: Issue → Actions → typed `linkedin.job.lookup` execution → structured result comment → automatic issue closure, using public data only.

## Known limitations

- the CLI operates on a local filesystem Workspace; it does not manage or synchronize Google Drive or other remote storage;
- ChatGPT Project configuration is manual in v0.1;
- ChatGPT host compatibility must remain documented/unverified until the real release smoke is recorded;
- Source Policy is hard-enforced only where Chat Harness controls the source-access boundary; host-native retrieval can only be policy-aware;
- the Playwright helper is bounded infrastructure, not a complete network-egress sandbox;
- no generic provider hierarchy, workflow engine, scheduler, model abstraction, vector-memory system, migration framework, full-screen TUI, or arbitrary browser/shell/HTTP capability is included;
- Claude and other assistants are architecturally applicable but not claimed as verified v0.1 integrations.

## Publication gates

This draft is not a release announcement. Repository rename/public visibility, tag, GitHub Release creation, and npm publication occur only after explicit maintainer approval and final hosted-smoke evidence.
