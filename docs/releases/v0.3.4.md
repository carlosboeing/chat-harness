# Chat Harness v0.3.4

This patch release fixes Workbench-to-Workstream backlink validation discovered during a clean v0.3.3 ChatGPT Research Workspace test.

## Fixed

ChatGPT naturally persisted Workbench ownership links as Workspace-relative paths:

```yaml
workstream: .chat-harness/workstreams/2026-09-28-home-dev-backup-disaster-recovery.md
```

The validator previously accepted only artifact-relative paths such as:

```yaml
workstream: ../../workstreams/2026-09-28-home-dev-backup-disaster-recovery.md
```

Both forms point to the same canonical Workstream, but the first incorrectly failed with `workbench.workstream_invalid`.

v0.3.4 now:

- accepts canonical Workspace-relative `.chat-harness/workstreams/....md` backlinks;
- keeps the existing artifact-relative `../../workstreams/...` form backward compatible;
- still rejects references that escape `.chat-harness/workstreams/`;
- updates published Workbench templates to prefer Workspace-relative backlinks.

## Prompt budget

No new always-on agent instructions were added. This is intentionally a deterministic validator/template fix rather than another rule in `AGENTS.md`.

## Upgrade

```bash
chat-harness update
chat-harness --version
chat-harness validate
```

Existing v0.3.3 Workspaces do not need `chat-harness setup` for this patch because the managed Project Instructions are unchanged.
