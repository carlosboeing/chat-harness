# Chat Harness v0.3.3

This patch release hardens durable-state reconciliation after a real ChatGPT Research Workspace test exposed stale Workstream state across turns.

## Improved

- Reconcile the owning canonical Workstream after material Workbench or state changes.
- Treat a checkpoint as complete only after the canonical Workstream reflects the latest durable state and has been re-read successfully.
- Prefer updating an existing same-purpose Workbench artifact instead of creating parallel near-duplicates.
- Classify artifacts by their primary durable purpose; experiment and benchmark protocols are plans, while their results remain research.
- Require exactly one H1 matching frontmatter `title` for Workstreams and Workbench artifacts.
- Keep the portable `AGENTS.md` high-signal: the new persistence rules were added while reducing the instruction file below a stricter 7,000-character budget.

## Validation and evals

- Workstream and Workbench validators now enforce H1/title agreement.
- Validation tests cover the title-heading contract.
- The behavioral eval catalog now includes a multi-turn plan-reconciliation regression scenario derived from the real-host local-AI test.
- Architecture and concepts documentation now define canonical checkpoint completion explicitly.

## Why this matters

A previous real-host run successfully created Idea, Research, Decision, and Plan artifacts, but left the canonical Workstream stale and later created a second plan-like artifact under Research. v0.3.3 tightens the contract around the authoritative resume point without adding a larger always-on prompt.

## Upgrade

For a standalone installation:

```bash
chat-harness update
chat-harness --version
```

For an npm-managed installation:

```bash
npm install -g chat-harness@latest
chat-harness --version
```

After upgrading, rerun `chat-harness setup` inside each Workspace to refresh the managed `AGENTS.md`, then copy the complete refreshed `AGENTS.md` into the ChatGPT Project Instructions.
